<Section number="01" title="The problem">

Fixing a phone or a laptop usually means finding a repair shop, explaining the fault, waiting without news and wondering what it will cost. Trust IT is a repair booking site for customers: pick your device, describe the problem, choose a repair centre, then follow the repair with a tracking code.

</Section>

<Section number="02" title="What I built">

I built Trust IT as a solo project, from Figma designs: a Next.js site and a NestJS server.

The site has a booking wizard that walks from device type to brand, range, model and problem. Signed-in customers see their repairs, each with a timeline of events, and without logging in anyone can track a repair by its code from the home page or the login page. Customers can also read offers, packages, the loyalty page, blogs and expert profiles, and post a short plain-text review.

</Section>

<Section number="04" title="Under the hood">

A pnpm monorepo with two apps: `apps/web` (Next.js 16, React 19, Tailwind) and `apps/api` (NestJS 11, Prisma 6, PostgreSQL).

The decision I would defend: the browser never holds the API token. Sign-in goes through Next route handlers that set an httpOnly cookie, and a same-origin proxy adds the bearer token on the way to the API. The proxy forwards only an allowlist of path prefixes, and the API rejects paths that do not match its routes exactly.

Other choices: database CHECK constraints for the rating (1 to 5), the comment length (500 characters), the IMEI (15 digits) and the tracking code (6 characters), so bad data fails at the lowest layer; and a global limit of 60 requests a minute per visitor IP, with stricter limits on login, tracking and reviews.

<Section number="05" title="API and backend">

The API exposes health checks (with and without the database), login and a demo login that only works when demo mode is on, the customer's profile, the device catalogue, repair centres and experts, tracking by code, repair CRUD limited to the customer's own repairs, reviews and blogs. Blog content is sanitised when it is read. A global JWT guard protects everything except routes marked public, input is validated with a whitelist, and every error has the same shape: status, code and message.

The API has 31 end-to-end tests (Jest and supertest, against a separate schema) covering login, repair creation, tracking, ownership, limits and the rate limit itself. CI runs lint, typecheck, tests and build on every push.

</Section>
